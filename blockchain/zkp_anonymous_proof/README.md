# ZKP Anonymous Membership Proof

On-chain Groth16 verifier for **anonymous set-membership proofs** on Ethereum.

A user proves they belong to an authorised group (stored as a Sparse Merkle Tree root on-chain) **without revealing which member they are**. A nullifier prevents the same identity from acting twice.

## Connection to HIDE

This contract is the on-chain counterpart to the [HIDE thesis](../../README.md#related-work):
- HIDE uses Groth16 (BN128) proofs off-chain to authenticate email senders anonymously.
- This contract does the same thing **on-chain** — any smart contract can call `verifyMembership()` to gate access without learning the caller's identity.

## How it works

```
Off-chain (prover / user):
  1. Generate identity_secret  (random, kept private)
  2. Compute leaf = Poseidon(identity_secret)
  3. Admin inserts leaf into Sparse Merkle Tree → merkleRoot updated on-chain
  4. To act anonymously:
       - Compute nullifierHash = Poseidon(identity_secret, external_nullifier)
       - Generate Groth16 proof of: "I know identity_secret s.t. leaf ∈ tree"
       - Submit proof + [merkleRoot, nullifierHash] to verifyMembership()

On-chain (AnonymousProver.sol):
  5. Check merkleRoot matches stored root
  6. Check nullifierHash has not been used before
  7. Run BN128 pairing check (Groth16 verification equation)
  8. If valid → mark nullifier used, emit event
```

## Groth16 verification equation

```
e(A, B) == e(α, β) · e(vk_x, γ) · e(C, δ)

where:
  A, B, C   = proof elements (from prover)
  α, β, γ, δ = verification key (from trusted setup)
  vk_x      = IC[0] + Σ input[i] · IC[i+1]   (linear combination of public inputs)
  e(·, ·)   = BN128 pairing  (EVM precompile 0x08)
```

The contract uses the BN128 precompiles at addresses `0x06` (ecAdd), `0x07` (ecMul), `0x08` (ecPairing) — available on all EVM chains since EIP-197.

## Setup — generate a real proof

```bash
# 1. Install toolchain
npm install -g circom snarkjs

# 2. Write a membership circuit (circom)
#    Circuit proves: prover knows identity_secret s.t.
#    Poseidon(identity_secret) is a leaf in the Merkle tree with known root

# 3. Compile
circom membership.circom --r1cs --wasm --sym

# 4. Trusted setup (Phase 1: powers of tau, Phase 2: circuit-specific)
snarkjs groth16 setup membership.r1cs pot15_final.ptau membership_0.zkey
snarkjs zkey contribute membership_0.zkey membership_final.zkey --name="Contributor"

# 5. Export Solidity verifier (replace VK values in AnonymousProver.sol)
snarkjs zkey export solidityverifier membership_final.zkey Verifier.sol

# 6. Compute witness & generate proof
node membership_js/generate_witness.js membership_js/membership.wasm input.json witness.wtns
snarkjs groth16 prove membership_final.zkey witness.wtns proof.json public.json

# 7. Verify off-chain
snarkjs groth16 verify verification_key.json public.json proof.json

# 8. Call on-chain
#    Parse proof.json → a, b, c arrays
#    Parse public.json → input array [merkleRoot, nullifierHash]
#    Call: AnonymousProver.verifyMembership(a, b, c, input)
```

## Security properties

| Property | Guarantee |
|----------|-----------|
| Zero-knowledge | Verifier learns nothing about identity_secret or Merkle path |
| Soundness | Cannot forge a valid proof without knowing a leaf in the tree |
| Nullifier | Same identity cannot act twice for the same external_nullifier |
| On-chain | No trusted third party needed after setup — pure smart contract |

## Curve & security level

BN128 (alt_bn128) — ~128-bit security. Same curve used in Ethereum's precompiles, Tornado Cash, Semaphore, Groth16 circuits generated by snarkjs.
